The rules this simulator implements

The daily rule & the four-way decision

AED 25.00 is assessed once per account per day when that day's closing ledger balance — all entries with valueDay ≤ day — is negative. The eligibility check includes prior-day fees but excludes the day's own fee or reversal, so a fee can never trigger itself:

Three triggers

1 · Movement — every booked movement walks its value day through the latest processed day (back-valued E7 walks D2→D5). 2 · Day advancement — when a successful command moves the latest processed day forward, the new days are assessed for every account, even if the command booked nothing (authorizations!). 3 · Report boundary — replay assessment extends to the final report day before interest capitalization.

Why the bound is not the command's own posted day

Caller order is authoritative and posted days need not be monotonic: a later-arriving command posted D5 can change an already-seen D6 closing. Rejected commands never move the bound — try the sandbox: a command posted on day 9 that gets rejected leaves everything untouched.

Scope notes

Only fee reconciliation is simulated — interest capitalization and instalment allocation are simplified (E10 books 3.334/3.333/3.333 BHD but no interest is accrued). Amounts are exact minor units; no floating point.
